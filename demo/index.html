1.2 为什么是现在

AI 微课已进入规模化生产阶段。AI 微课 Agent 每天产出大量 AIGC 内容（HTML 格式的互动微课），内容直接推送给学生。V1.0 的通用评估框架难以精准评估 AI 微课场景的核心质量要求（如互动设计有效性、数学内容准确性、生产一致性等），评估结果也无法直接服务于产品运营决策。建立专属评估框架和可视化后台是 AI 微课质量体系进入可持续运营阶段的关键基础设施。

1.3 核心痛点

AI 微课大规模输出 AIGC 内容，既缺乏与内容类型适配的评估框架，也缺乏对评估结果的统一可视化管理，产品团队无法有效监控内容质量并系统性驱动 AI 微课 Agent 优化。

二 Objective

2.1 目标

将 AI 微课 AIGC 内容评估系统从一个辅助工具升级为嵌入 AI 微课生产链路的系统性质量基础设施。每一份 AI 微课 Agent 产出的 AIGC 内容都自动完成六大维度评估、门控决策和结果沉淀；产品团队通过统一后台实时掌握内容质量全景，并获得数据驱动的 Agent 优化建议。

2.3 保留价值公式

场景 1：AI 微课内容发布门控 新体验（自动评估门控）- 旧体验（无门控直发）- 替换成本（等待评估时延） = 低质内容拦截价值 + 知识错误减少的用户信任损失 - 发布延迟成本 → 净正值，评估时间越短价值越大 场景 2：产品团队质量决策 新体验（后台看板 + 自动建议）- 旧体验（人工汇总 + 主观判断）- 替换成本（后台建设成本） = 决策效率提升 + 优化方向准确性提升 - 一次性开发成本 → 净正值，长期收益随内容规模增长 场景 3：AI 微课 Agent 优化驱动 新体验（数据驱动优化建议）- 旧体验（无数据驱动）- 替换成本（建议生成成本） = 每轮优化后质量提升量化可见 - 约等于零的边际成本 → 高净正值，形成数据飞轮

三 范围界定

In Scope（V2.0）
  • 评估 Agent 系统：接收 AI 微课 AIGC 内容，执行六大维度评估，输出评估结果并执行门控动作
  • 六大维度评估框架：合规安全性（硬门槛）、知识准确性（30分）、教学有效性（30分）、内容适配性（15分）、语言规范性（10分）、生产稳定性（15分）
  • Agent 对接自动触发：AI 微课 Agent 生成内容后通过 API 自动推送至评估 Agent，无需人工介入
  • 后台管理系统 - AIGC 内容列表页
  • 后台管理系统 - 评估看板
  • 后台管理系统 - AI 微课 Agent 优化建议模块
  • 评估框架版本管理：criteria 版本控制，评估结果可追溯、可复现
  • 安全告警链路：合规安全性硬门槛未过时实时告警
Out of Scope（V2.0）
  • 其他 Agent（老师 Agent、助教 Agent、助理 Agent）的接入（预留接口，V3.0 扩展）
  • 视频（.mp4）、文档（.docx/.pptx）类内容评估（V2.0 仅支持 HTML 格式）
  • 学生行为数据采集与分析（如游戏通关率）
  • 实际 SFT/RLHF 训练流程（评估系统只提供数据，不执行训练）
  • Agent 自主修改其他 Agent 逻辑（V2.0 只输出建议，不执行自动改写）
  • 多语言内容评估（V2.0 仅支持中文）
  • 学生/教师端任何评估维度或分数的展示

六 User Story

Story 1 AI 微课 Agent 自动触发评估，获取发布许可
As an AI 微课 Agent，I want 在每次完成 AIGC 内容生成后自动提交评估并等待结果，So that 只有通过六大维度评估的内容才会进入发布流程。
Acceptance Criteria
  • Given AI 微课 Agent 生成了一份高一数学等腰梯形向量综合 HTML 微课内容，When 评估 Agent 完成六大维度评估（约 30-90s），Then：若合规安全性通过且 total_score ≥ 85，返回 verdict: approved，AI 微课 Agent 执行发布
  • 若 total_score 在 70-85 之间或某维度低于阈值，返回 verdict: needs_revision + fix_instructions，AI 微课 Agent 修改后重提交
  • 若合规安全性不通过，返回 verdict: rejected，触发实时告警至产品安全团队
Edge Cases
  • 评估超过 90s → 返回 verdict: timeout，AI 微课 Agent 可设定重试策略或进入人工审核队列
  • 连续第 4 次被返回 needs_revision → 系统告警，内容进入人工审核队列，AI 微课 Agent 暂停该内容自动重提交
  • HTML 文件 URL 不可访问 → 返回 400 + preprocessing_failed，AI 微课 Agent 重新上传文件后重试
  • educational_context 中 grade/subject 缺失 → 返回 400，AI 微课 Agent 补全元数据后重试
Story 2 AI 产品经理通过看板快速掌握内容质量状况
As an AI 产品经理，I want 每周在评估看板查看 AIGC 内容的整体质量趋势和维度均分，So that 能快速判断质量是否在改善、哪个维度需要重点关注。
Acceptance Criteria
  • Given AI 产品经理打开评估看板，选择"近 7 天"时间范围，When 看板数据加载完成（≤ 2s），Then：核心 KPI 卡片展示总评估量、通过率、平均分、安全拦截量及环比变化
  • 通过率趋势折线图展示近 14 天每日通过率
  • 各维度平均分横向对比，清晰展示哪个维度均分最低
  • 点击任意维度可下钻至内容列表，自动过滤该维度低分内容
Edge Cases
  • 所选时间范围内无评估记录 → 展示空态提示，不展示 0%（避免误导）
  • 某维度因预处理失败被大量跳过 → 该维度显示"数据不足"标注，不参与均分计算
Story 3 AI 产品经理查看优化建议，推动 Agent 优化
As an AI 产品经理，I want 查看系统自动生成的 AI 微课 Agent 优化建议，So that 能有数据支撑地向 AI 算法团队提出优先级明确的优化需求。
Acceptance Criteria
  • 建议包含：目标维度、问题描述、量化数据佐证（N 条内容受影响，均分 X/Y）
  • 提供优化方向说明（具体到 Prompt 调整或生产流程改进方向）
  • 点击"查看相关内容"直接跳转至已过滤的内容列表
  • 点击"已采纳"后状态更新，后续周报追踪该维度分数变化
Edge Cases
  • 近 14 天评估数据不足 50 条 → 建议生成跳过，展示"数据量不足，建议积累更多评估数据后生成"
  • LLM 生成建议失败 → 展示上次成功生成的建议，附时间戳，不展示空态
Story 4 研发人员下钻定位具体内容生产问题
As an AI 算法工程师，I want 在内容列表中找到评分低的内容，查看细粒度评估报告，So that 精准定位 AI 微课 Agent 在哪个生产步骤出现问题。
Acceptance Criteria
  • 展示各二级指标的具体得分和问题描述（如"P4b 三个卡片内容区域为空"）
  • 展示修改建议（具体到页面级、字段级）
  • 可查看原始 AIGC HTML 内容预览
  • 可手动触发重新评估（当 Agent 修改后）
Edge Cases
  • 原始内容 URL 已失效 → 内容预览展示"原始内容已过期"提示，其他功能不受影响

十二 风险登记册

#风险严重程度概率缓解策略
1 主观维度（教学有效性/知识准确性）LLM 评估结果不稳定 高 中 temperature=0 + seed 固定 + 定期重评监控（≤ 2分漂移阈值）；初版阈值偏宽松
2 六大维度阈值设置不合理导致大量误拒，阻塞 AI 微课 Agent 生产效率 高 中 Phase 1-2 先用 advisory 模式收集数据，基于真实数据校准阈值后再开启 blocking 门控
3 HTML 内容结构差异大，DOM 解析无法覆盖所有 AI 微课模板 中 高 与 AI 微课 Agent 团队约定 AIGC 内容的 HTML 结构规范（class 命名约定），预处理层支持多模板匹配
4 Blocking 评估延迟超过 90s，阻塞 AI 微课内容发布流程 高 低 设置超时 fallback（verdict: timeout），允许人工决策兜底；并行优化 Agent 评估效率
5 AI 微课 Agent 改造接入工作量超预期，影响 Phase 3 排期 中 中 Phase 3 前提前启动 Agent 改造评估（W2 完成接口定义），预留 1 周缓冲
6 合规安全性误拦截正常教学内容，影响 AI 微课 Agent 生产效率 高 低 合规安全性 Agent 采用双重检测（词库 + LLM），建立白名单机制，初期允许安全团队快速解除误拦截
7 优化建议质量低，产品团队不信任 / 不采纳 中 中 Phase 4 前先做 1-2 次人工验证：人工汇总数据生成建议，与系统自动建议对比，校准 Prompt
8 知识库 RAG 覆盖不全（尤其高中数学），知识准确性评估误判 中 高 RAG 不可用时降级为 LLM 内部知识，结果标注不确定性；同步跟进知识库建设
